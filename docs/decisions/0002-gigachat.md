# 0002. GigaChat как основная LLM, YandexGPT в резерве, и только там, где ошибка не критична

**Дата.** 2026-10-09

**Контекст.** ТЗ считает преимуществом ML и NLP для разбора резюме и подбора, но требует сопоставимой и объективной оценки. Команда выбрала отечественную модель.

**Решение.** GigaChat (`gigachat` 0.1.40) используется для разбора резюме, оценки ответов на короткие задания и разбора решений Code Arena. Без ключа эти функции работают на правилах. Задания теста, их ответы, грейд и подборку модель не трогает.

**Альтернативы.**
- Генерация заданий моделью под каждого — несопоставимая сложность, риск неверного ключа ответа (прямо отмечено в ТЗ).
- Эмбеддинги для подбора — меньше объяснимости, а объяснимость выдачи — требование ТЗ.

**Последствия.** Продукт полностью работает без ключа и без сети к модели; модель улучшает удобство, не влияя на честность оценки.

## Дополнение от 2026-10-10: резервный провайдер YandexGPT

**Контекст.** На площадке ключ GigaChat был задан, но разборы шли от правил: у одного провайдера бывают отказы авторизации, лимиты и недоступность сети, а снаружи этого не видно.

**Решение.** Вызовы модели идут через цепочку `app.llm.chain`: GigaChat, затем YandexGPT (`yandexgpt-lite` в Yandex AI Studio), затем правила у вызывающего кода. Порядок задаёт `LLM_PROVIDERS`. Кто написал результат, видно в поле `source` и в интерфейсе. Состояние провайдеров показывает `GET /api/v1/llm/status`. Границы применения модели не меняются. Спека — [llm-provajdery.md](../specs/llm-provajdery.md).

**Альтернативы.**
- Только GigaChat — при отказе ключа пользователи молча получают правила.
- Сторонняя зарубежная модель — противоречит выбору отечественных сервисов и требует передачи данных за рубеж.

**Последствия.** Отказ одного провайдера не снижает качество разборов; оба ключа хранятся только в окружении площадки.
