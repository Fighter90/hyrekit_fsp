# 0005. ФСП через интерфейс провайдера и детерминированный эмулятор

**Дата.** 2026-10-09

**Контекст.** API и структура данных реестра ФСП не предоставлены намеренно; ФСП ID в будущем — на Keycloak. Обязательна обработка кандидата без истории.

**Решение.** Протокол `FspProvider.fetch(fsp_id)` и `MockFspProvider`, детерминированный по ID; ID на 0 — без истории. Ответ сохраняется снимком в профиле. Целевая схема — OIDC Authorization Code + PKCE с Keycloak и API достижений, описана в разделе 4 документации.

**Альтернативы.**
- Ручной ввод достижений кандидатом — непроверяемо, противоречит идее подтверждённого профиля.
- Сразу интегрироваться с Keycloak — нечего интегрировать без стенда ФСП.

**Последствия.** Замена эмулятора — одна реализация протокола; кабинеты и рейтинг не меняются.

**Обновление 2026-10-10 (FSP-20).** Вход и привязка через ФСП ID реализованы по OpenID Connect (Authorization Code + PKCE), см. раздел 4 документации и спецификацию `docs/specs/fsp-20-fsp-id-oidc.md`. Пока Keycloak ФСП недоступен, приложение поднимает встроенный провайдер по тому же протоколу; клиент работает с ним по HTTP, переход на Keycloak — переменные `FSP_OIDC_*`. Альтернатива «доверять ручному вводу» отвергнута: подтверждённый `sub` провайдера отличает владельца идентификатора от того, кто вписал чужой ID.
