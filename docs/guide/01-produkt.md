# 1. Продукт

## Проблема

Универсальные площадки поиска работы не решают задачу ни одной из сторон. Работодатель вручную разбирает сотни нерелевантных откликов силами дорогих инженеров. Кандидат откликается вслепую и не получает ответа. В ИТ это усугубляется тем, что резюме фиксирует стек и места работы, но не подтверждает умение: отбор сводится к совпадению ключевых слов (ТЗ, п. 1).

## Обратная механика

HyreKit переворачивает привычный путь. Инициатива у работодателя:

1. Кандидат один раз проходит обязательный путь: опрос по отрасли и специализации, выбор грейда, тест на этот грейд.
2. Тест присваивает **категорию** — связку специализации и грейда, например «Backend · Middle». Самоописание из резюме на категорию не влияет.
3. Внутри категории кандидаты ранжируются по силе подтверждённого профиля: результат теста, достижения ФСП, свежесть активности.
4. Работодатель описывает потребность и получает подборку с объяснением, почему каждый кандидат в ней. Он сам выбирает человека и отправляет **приглашение с вилкой зарплаты** — кандидат видит условия до начала общения.
5. Контакты кандидата скрыты, пока он не принял приглашение или не откликнулся сам.

Классический отклик на вакансию тоже есть, но как дополнение: кандидат, которого ещё не пригласили, может проявить инициативу сам (ТЗ, п. 2.1).

## Роли

| Роль | Что делает |
| -- | -- |
| Кандидат | Заполняет профиль вручную или загрузкой PDF, проходит опрос и тест, получает категорию, привязывает ФСП ID, управляет приватностью, принимает или отклоняет приглашения, откликается на вакансии, решает короткие задания работодателей |
| Работодатель | Ведёт профиль компании, описывает потребности (вакансии), получает подборку с объяснением, ищет по банку кандидатов, отправляет приглашения, видит тест под вакансию, публикует вакансии и разбирает отклики, ставит короткие задания |

Роль выбирается при регистрации. Эндпоинты кабинета кандидата недоступны работодателю и наоборот; каждый видит только свои записи.

## Что такое категория и грейд

| Грейд | Типичный опыт | Уровень заданий |
| -- | -- | -- |
| Intern | без опыта | 1 |
| Junior | до 1–2 лет | 2 |
| Middle | 2–4 года | 3 |
| Senior | 4–7 лет | 4 |
| Lead | 7+ лет | 5 |

Направления MVP: Backend, Frontend, Data Science / ML, DevOps / SRE, QA, информационная безопасность. Справочник лежит в `src/app/catalog/data.py`, отдаётся эндпоинтом `GET /api/v1/catalog`.

## Границы MVP

Входит:

- оба кабинета со всеми обязательными пунктами ТЗ 2.1 и правилами видимости 2.2;
- регистрация по почте с подтверждением адреса;
- вход и привязка через ФСП ID по OpenID Connect: встроенный тестовый провайдер, Keycloak ФСП подключается переменными `FSP_OIDC_*`;
- экспресс-тест для жюри: 5 заданий без регистрации;
- механика тестирования с параметрическими заданиями и оценкой способности;
- подборка с объяснимостью, поиск с фильтрами, приглашения со статусами;
- дополнительный функционал: публичные вакансии и отклики, регулярные короткие задания, Code Arena с автопроверкой и рейтингом, адаптивная вёрстка;
- LLM для разбора резюме, оценки коротких заданий и разбора решений Arena: GigaChat → YandexGPT → правила;
- эмулятор реестра ФСП с корректной обработкой кандидата без истории;
- валидация методики на синтетических данных с воспроизводимым скриптом.

Не входит в MVP (концепция и архитектурный подход — в [разделе 4](04-arhitektura.md)):

- реальная интеграция с реестром ФСП;
- защита от фиктивных вакансий и недобросовестных работодателей, верификация компаний;
- интеграция с ATS работодателей.

## Почему это работает для обеих сторон

| Сторона | Было | Стало |
| -- | -- | -- |
| Работодатель | Сотни откликов, ручная фильтрация по ключевым словам | Подборка из категории, подтверждённой тестом, с причинами попадания и недостающим стеком |
| Кандидат | Отклик вслепую, зарплата неизвестна | Приглашение приходит само, вилка зарплаты видна сразу, контакты раскрываются только с согласия |
| Участник ФСП | Спортивные результаты не видны на рынке труда | Достижения автоматически попадают в профиль и поднимают кандидата внутри категории |
