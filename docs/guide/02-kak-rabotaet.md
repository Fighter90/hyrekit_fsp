# 2. Как работает

Сквозной сценарий из ТЗ 3.3: регистрация соискателя → опрос и тест → категория → работодатель находит категорию → приглашение → контакт. Плюс классический отклик на вакансию.

## Кандидат

| Шаг | Экран | Что происходит в системе | API |
| -- | -- | -- | -- |
| 1 | Регистрация | Роль «кандидат», письмо со ссылкой подтверждения адреса | `POST /auth/register`, `GET /auth/verify/{token}` |
| 2 | Профиль | Ручное заполнение или загрузка PDF/DOCX. Текст разбирается правилами и, если подключён GigaChat, моделью: ФИО, контакты, стек, роли, стаж, софт-скиллы | `PUT /candidate/profile`, `POST /candidate/profile/resume` |
| 3 | Опрос | Отрасль, специализация, стаж, стек, предполагаемый грейд | `POST /candidate/assessment/survey` |
| 4 | Тест | 10 заданий по 5 темам специализации, 20 минут, ответы сохраняются по одному, попытку можно продолжить | `POST /candidate/assessment/start`, `.../answer`, `.../finish` |
| 5 | Результат | Оценка способности θ, балл 0–100, разбор по темам. Сдал — грейд и категория присвоены. Не сдал — грейд не меняется, система предлагает тест уровнем ниже. Сдал уверенно — предлагает уровень выше | `GET /candidate/assessment/history` |
| 6 | Настройки | Согласие на обработку и публикацию (152-ФЗ), что видно работодателю, ФСП ID | `PUT /candidate/settings` |
| 7 | Приглашения | Компания, описание предложения, вилка зарплаты, способ связи. Принять — работодатель видит контакты; отклонить — с причиной | `GET /candidate/invitations`, `.../accept`, `.../decline` |
| 8 | Вакансии | Список опубликованных вакансий, отклик с сообщением, статусы откликов | `GET /candidate/vacancies`, `POST .../apply` |
| 9 | Задания | Короткие задачи от работодателей: ответ оценивается GigaChat по рубрике или эвристикой без модели, профиль становится «свежее» | `GET /candidate/challenges`, `POST .../submit` |
| 10 | PDF-профиль | Стандартизированный профиль в фирменной гарнитуре | `GET /candidate/profile/pdf` |

Работодатель видит кандидата, только когда у него есть категория **и** согласие на публикацию.

## Работодатель

| Шаг | Экран | Что происходит в системе | API |
| -- | -- | -- | -- |
| 1 | Регистрация | Роль «работодатель» | `POST /auth/register` |
| 2 | Компания | Название, направление, описание, контакты | `GET/PUT /employer/company` |
| 3 | Потребность | Кого ищем, чем занимается команда, специализация, диапазон грейдов, стек, вилка зарплаты (обязательна), формат работы | `POST /employer/vacancies` |
| 4 | Подборка | Категории с числом кандидатов, список по убыванию соответствия, разложение балла и причины: «Категория Backend · Middle входит в диапазон», «Стек: 4 из 5», «ФСП: 2 соревнования, лучшее место — 1». Фильтры по грейду, стеку и ФСП уточняют список, не сбрасывая подборку | `GET /employer/vacancies/{id}/matches` |
| 5 | Тест под вакансию | Темы теста, выведенные из стека вакансии, и два варианта с разными заданиями и одинаковой сложностью | `GET /employer/vacancies/{id}/assessment` |
| 6 | Банк кандидатов | Поиск по всей базе: специализация, грейд, категория, стек, наличие достижений ФСП, текст | `GET /employer/candidates` |
| 7 | Приглашение | Описание, вилка «от–до» в рублях, способ связи; без обязательной привязки к вакансии. Повторное приглашение, пока первое не закрыто, запрещено (409) | `POST /employer/invitations` |
| 8 | Статусы | отправлено → просмотрено → принято / отклонено; после принятия видны ФИО и контакты | `GET /employer/invitations` |
| 9 | Отклики | Входящие отклики на вакансии, смена статуса; откликнувшийся кандидат раскрывает контакты сам | `GET /employer/applications`, `POST .../status` |
| 10 | Задания | Короткие задачи для кандидатов направления и ответы на них с оценкой | `GET/POST /employer/challenges` |

## Правила видимости (ТЗ 2.2)

| Правило | Где в коде |
| -- | -- |
| Зарплата обязательна в вакансии и приглашении, `from ≤ to` | схемы `VacancyIn` и `InvitationIn` в `src/app/employers/router.py` |
| Контакты скрыты до принятия приглашения или отклика | `candidates.service.to_card`, `hiring.service.unlocked_profiles` |
| Без согласия и категории профиль не виден | `candidates.service.is_visible` |
| Скрытое ФИО заменяется псевдонимом «Кандидат #A1B2» | `candidates.service.public_alias` |
| Кандидат видит только свои приглашения и отклики | фильтр по `profile_id` во всех запросах `/candidate/*` |
| Смена грейда не чаще раза в 90 дней | `assessment.service.eligibility` |
