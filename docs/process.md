# Процесс разработки

## Источник истины

Задачи — в Linear, проект «HyreKit — платформа подбора ИТ-специалистов (ФСП)», ключи `FSP-N`. Две вехи: «Промежуточная сдача» и «Финальная сдача». Эпики соответствуют критериям оценки ТЗ.

## Путь задачи (Spec-Driven Development)

1. **Задача** в Linear: контекст, что сделать, правила и числа со ссылками на ТЗ, критерии приёмки, как проверить.
2. **Спецификация** `docs/specs/fsp-N-<slug>.md` по шаблону: сценарии, правила, критерии приёмки в формате EARS («WHEN … THE SYSTEM SHALL …»), план тестов.
3. **Контракт** — изменения API сначала в `docs/spec/api.md`, затем в коде; фронтенд и бэкенд идут параллельно по контракту.
4. **Код и тесты**: на каждый критерий приёмки — тест.
5. **Решение с альтернативами** — ADR в `docs/decisions/`.
6. **Документация** — раздел `docs/guide/`, если меняется поведение, видимое жюри.

## Ветки и коммиты

- `main` — всегда собирается и проходит CI.
- Ветка на задачу: `fsp-N-<slug>`; сообщение коммита начинается с ключа: `FSP-44: объяснимость подборки`.
- Слияние после зелёного CI.

## Definition of done

- Критерии приёмки спецификации покрыты тестами и проходят.
- `ruff check`, `ruff format --check`, `pytest`, `npm run lint`, `npm run build`, `npm test` — зелёные.
- Если менялась методика — пересчитан `docs/validation/results.md`, цифры в `docs/guide/03-metodika-ocenki.md` совпадают с ним.
- Задача в Linear переведена в Done со ссылкой на коммит.
