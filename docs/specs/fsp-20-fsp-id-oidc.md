# Вход и привязка через ФСП ID (OpenID Connect)

Linear: FSP-20 · веха Финальная сдача. Пункты ТЗ: 2 (данные ФСП, подтверждённый профиль).

## Цель
ФСП ID, введённый вручную, ничего не доказывает: любой может вписать чужой идентификатор и получить чужие достижения в рейтинг. Вход через ФСП ID подтверждает, что участник владеет идентификатором. Работодатель видит отметку «подтверждён ФСП ID», а участник ФСП входит в HyreKit без отдельного пароля.

## Для кого
- Участник ФСП, который хочет войти одной кнопкой и сразу получить профиль с достижениями.
- Кандидат с аккаунтом HyreKit, который хочет подтвердить свой ФСП ID.
- Работодатель, который отличает подтверждённые достижения от введённых вручную.

## Сценарии
1. Вход. На странице входа кандидат нажимает «Войти через ФСП ID», попадает на страницу провайдера, входит и разрешает передачу данных. Возвращается в HyreKit уже вошедшим. Новый участник получает аккаунт кандидата с подтверждённым ФСП ID и достижениями, повторный вход ведёт в тот же аккаунт.
2. Привязка. В «Настройках» кандидат нажимает «Привязать через ФСП ID» (или «Подтвердить через ФСП ID», если ID был введён вручную). После возврата ФСП ID привязан с отметкой «подтверждён ФСП ID».
3. Отказ. На странице провайдера кандидат нажимает «Отмена» и видит в HyreKit «Вход через ФСП ID отменён».
4. Работодатель в карточке кандидата видит у достижений «подтверждён ФСП ID» или «введён вручную».

## Правила и числа
- Протокол: OpenID Connect Authorization Code + PKCE (S256), discovery, проверка `id_token` (подпись, `iss`, `aud`, `exp`, `nonce`) и `sub` из userinfo. Клиент конфиденциальный: код обменивает бэкенд с `client_secret`.
- `state`, `nonce` и `code_verifier` хранятся в подписанной HttpOnly-cookie `fsp_oidc` (путь `/api/v1/auth/fsp`, SameSite=Lax, Secure на https), срок 10 минут. Cookie удаляется после обмена.
- ФСП ID берётся из claim `FSP_OIDC_ID_CLAIM` (по умолчанию `fsp_id`), иначе из `preferred_username`; формат `FSP-NNNN…`.
- Один участник ФСП (`sub` провайдера) подтверждён не более чем в одном профиле. Попытка привязать его ко второму аккаунту даёт 409.
- Вход: сначала профиль с этим `sub`. Иначе кандидат с той же почтой, если провайдер подтвердил почту (`email_verified`). Иначе новый подтверждённый кандидат. Работодатель через ФСП ID не входит.
- Ручной ввод другого ФСП ID или отвязка снимают подтверждение.
- Провайдер задаётся переменными `FSP_OIDC_*`. Пока Keycloak ФСП недоступен, приложение поднимает встроенный тестовый провайдер с тем же протоколом (`/api/v1/fsp-id`, тестовые участники `FSP-123457` и `FSP-123450`, пароль `fsp2026`). Переход на Keycloak — переменные окружения, без изменений кода.

## Вне scope
- API достижений реестра ФСП: достижения по-прежнему берёт `FspProvider` (ADR 0005).
- Выход из сессии провайдера (RP-initiated logout) и back-channel logout.
- Вход работодателя через ФСП ID.

## Данные
- `candidate_profiles.fsp_sub` — `sub` участника у провайдера, уникальный; пусто, если ФСП ID введён вручную. Миграция `0007_fsp_oidc`.
- В сводке ФСП (`fsp`) поле `verified`.

## Критерии приёмки (EARS)
- WHEN кандидат входит через ФСП ID впервые THE SYSTEM SHALL создать подтверждённого кандидата с ФСП ID, достижениями и `verified = true`.
- WHEN тот же участник входит снова THE SYSTEM SHALL войти в тот же аккаунт.
- WHEN `state` не совпадает с cookie или cookie нет THE SYSTEM SHALL отказать с 400.
- WHEN код авторизации используется повторно или `code_verifier` не совпадает THE SYSTEM SHALL отказать (`invalid_grant`).
- WHEN `nonce` в `id_token` не совпадает с ожидаемым THE SYSTEM SHALL отклонить вход.
- WHEN кандидат отменяет вход у провайдера THE SYSTEM SHALL показать «Вход через ФСП ID отменён».
- WHEN `redirect_uri` не зарегистрирован THE SYSTEM SHALL отказать на странице провайдера.
- WHEN вошедший кандидат привязывает ФСП ID THE SYSTEM SHALL сохранить `sub` и показать «подтверждён ФСП ID».
- WHEN тот же участник ФСП привязывается ко второму аккаунту THE SYSTEM SHALL ответить 409.
- WHEN привязку завершает другой пользователь, чем начал THE SYSTEM SHALL ответить 403.
- WHEN кандидат вручную меняет ФСП ID THE SYSTEM SHALL снять подтверждение.
- WHEN вход через ФСП ID не настроен THE SYSTEM SHALL скрыть кнопки.

## Интерфейсы
- `GET /api/v1/auth/fsp/config` → `{enabled, test_provider}`.
- `POST /api/v1/auth/fsp/start {mode: login | link}` → `{authorize_url}` и cookie `fsp_oidc`; `link` только для вошедшего кандидата.
- `POST /api/v1/auth/fsp/callback {code, state}` → `{mode, fsp_id, created, tokens}`; токены только для `login`.
- Тестовый провайдер: `GET /api/v1/fsp-id/.well-known/openid-configuration`, `GET|POST /authorize`, `POST /token`, `GET /userinfo`, `GET /jwks`.
- Фронтенд: кнопка на `/auth`, страница возврата `/fsp-callback`, кнопки в «Настройках».
