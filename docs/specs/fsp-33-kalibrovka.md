# Калибровка заданий и мониторинг утечек

Linear: FSP-33 · веха Финальная сдача. Пункты ТЗ: 2.1 «Механика тестирования», устойчивость к распространению заданий.

## Цель
Генеративные задания уже не дают переносить шпаргалку дословно. Это вторая линия защиты: если семейство заданий вдруг решается заметно лучше, чем предсказывает модель, его ответы, вероятно, разошлись. Такое семейство нужно найти и снять с выдачи, а также уточнять трудность семейств по накопленным ответам.

Решено, когда симулированная утечка обнаруживается, семейство исключается из новых попыток, а у команды есть отчёт о статусе всех семейств.

## Для кого
- Команда HyreKit: видит статус семейств и вовремя заменяет утёкшие.
- Работодатель: доверяет грейду, даже если часть заданий где-то опубликована.

## Сценарии
1. Кандидаты проходят тесты, ответы копятся.
2. Раз в час приложение пересчитывает статистику семейств за последние дни. Семейство со статусом «утечка» исключается из планов новых попыток.
3. Команда запускает `scripts/calibrate.py` и получает таблицу: показы, доля верных, ожидаемая доля, дрейф, z, сдвиг трудности и статус каждого семейства.

## Правила и числа
Числа живут в `src/app/assessment/calibration.py`, обоснование порогов — в `docs/validation/results.md`, раздел 6.
- Для каждого ответа способность кандидата оценивается заново только по генеративным заданиям той же попытки без самого задания. Так утёкшее задание не завышает оценку, по которой его же проверяют.
- Ожидаемая вероятность верного ответа — модель Раша с номинальной трудностью уровня задания.
- Дрейф семейства — доля верных минус ожидаемая, за вычетом общего сдвига всех семейств (медиана). Общий сдвиг даёт стягивание MAP-оценки к порогу грейда.
- Утечка — дрейф выше порога **и** z-статистика выше порога при достаточном числе показов. Порог дрейфа ниже 15 п.п. из постановки: при 15 п.п. утечка к четверти кандидатов проходит незамеченной (см. валидацию). Ложные тревоги отсекает z.
- Обратный дрейф — статус «сложнее ожидаемого», задание не исключается.
- Сдвиг трудности семейства — MAP-оценка с априорным нормальным распределением вокруг нуля.
- Если в теме на уровне не осталось других семейств, исключённое всё же выдаётся: тест без темы хуже.
- Исключённое семейство остаётся исключённым, пока команда его не заменит: новых показов у него нет, и статус не меняется.
- На PostgreSQL калибровку ведёт один воркер (advisory lock).

## Вне scope
- Задачи прошлых соревнований ФСП: в банке их нет; реестр ФСП не отдаёт, кто какие задачи решал.
- Сигналы списывания в тесте (время ответа, уход со вкладки): в тесте на грейд время ответов не хранится; сигналы пишутся в Code Arena (FSP-38).
- Веб-страница для команды: ролей администратора нет, статус выдаёт отчёт `scripts/calibrate.py`.

## Данные
- `item_calibration` — статус семейства по последней калибровке: тема, показы, верные, доля верных и ожидаемая, дрейф, z, сдвиг трудности, статус (`ok`, `leak`, `hard`, `few`), признак исключения, время калибровки.

## Критерии приёмки (EARS)
- WHEN часть кандидатов знает ответы одного семейства THE SYSTEM SHALL присвоить ему статус «утечка» и не выдавать его в новых попытках.
- WHEN ответы честные THE SYSTEM SHALL не помечать ни одно семейство как утечку.
- WHEN у семейства мало показов THE SYSTEM SHALL не принимать по нему решения.
- WHEN команда запускает `scripts/calibrate.py` THE SYSTEM SHALL вывести таблицу статусов всех семейств.
- WHEN приложение работает THE SYSTEM SHALL пересчитывать статусы по расписанию `CALIBRATION_INTERVAL_MINUTES`.

## Интерфейсы
- `calibration.attempt_observations(plan, answers, grade)` → наблюдения попытки; `calibration.family_stats(observations)` → статистика и статусы.
- `assessment.service.recalibrate(session, window_days)` — пересчёт и запись; `excluded_families(session)` — исключённые семейства; `engine.build_blueprint(..., excluded=...)`.
- `scripts/calibrate.py [--days N] [--dry-run] [--out файл]`.

## План тестов
- `tests/test_method/test_calibration.py`: честная популяция без тревог; симулированная утечка обнаружена и легче номинала; мало показов — без решения; план не содержит исключённых; пересчёт пишет статус в базу и новая попытка обходит утёкшее семейство.
- `scripts/validate.py`, раздел 6: ложные тревоги на 2 000 честных попытках, обнаружение при 25, 50 и 75 % знающих ответы, отсутствие показов после исключения.
