# Code Arena: соревнования по коду, автопроверка и рейтинг

Linear: FSP-36 (эпик), FSP-37, FSP-38, FSP-39, FSP-40, FSP-41, FSP-42 · веха Финальная сдача. Пункты ТЗ: 2.2 «Выход на контакт», «Дополнительный функционал», «Регулярные задания от работодателя».

## Цель
Кандидат решает задачи по программированию в браузере, код проверяется автоматически на скрытых тестах, кандидат получает разбор решения и рейтинг Arena. Работодатель видит лучших по рейтингу, проводит свой раунд на задачах из банка и приглашает участников прямо из таблицы.

Решено, когда сквозной сценарий проходит в браузере на стенде: кандидат открывает раунд, пишет решение, видит вердикт по тестам и разбор, попадает в таблицу и в рейтинг, работодатель находит его и приглашает.

## Для кого
- Кандидат: показать навык кодом, а не только тестом на грейд.
- Работодатель: не ждать откликов, а забрать сильных по объективному сигналу.
- Эксперт жюри: попробовать Arena в любой момент на открытом раунде.

## Сценарии
1. Кандидат открывает «Arena», видит открытый раунд и раунды работодателей, нажимает «Участвовать».
2. Для участника запускается таймер. У каждой задачи свой вариант: та же идея и сложность, другие данные и примеры.
3. Кандидат пишет код в редакторе, нажимает «Запустить на примерах» и видит результат по каждому примеру. Попытка не засчитывается.
4. Кандидат нажимает «Отправить». Решение проверяется на скрытых тестах, вердикт и время по каждому тесту появляются без перезагрузки страницы.
5. После проверки кандидат читает разбор: что не так (первый непройденный тест, типичная причина), оценку сложности решения и советы. Разбор пишет модель по цепочке GigaChat → YandexGPT, если не ответила ни одна — правила по результатам тестов и разбору кода.
6. Таблица раунда обновляется у всех участников без перезагрузки.
7. Когда время участника вышло или он завершил раунд досрочно, пересчитывается рейтинг Arena, открываются эталонные решения и статистика по задачам.
8. Работодатель открывает «Arena»: витрина кандидатов по рейтингу с фильтрами, создание своего раунда, таблица любого раунда с кнопкой «Пригласить».
9. Кандидат принимает приглашение, контакты раскрываются по обычным правилам приглашений (FSP-46).

## Правила и числа
Числа живут в `src/app/arena/judge.py`, `src/app/arena/service.py` и `src/app/arena/rating.py`; здесь только смысл.

**Песочница (FSP-37).**
- Языки: Python 3 и JavaScript (Node.js). JavaScript включается, только когда ядро даёт оба слоя изоляции (Landlock и seccomp, см. ниже); без них доступен только Python под аудит-хуком.
- Каждый тест — отдельный процесс с лимитами ОС: процессорное время, память, размер файлов, число открытых файлов, без core-дампов, с пустым окружением во временной папке. Настенное время ограничено, вывод обрезается.
- Python запускается в изолированном режиме с аудит-хуком: запрещены сеть, запуск процессов, `fork`, `ctypes`, сигналы другим процессам, запись файлов и чтение файлов вне стандартной библиотеки. Нарушение даёт вердикт RE с понятным сообщением.
- Изоляция ядром (`src/app/arena/sandbox.py`): перед запуском интерпретатора обёртка включает Landlock (чтение только каталогов интерпретатора, системных библиотек и папки решения; запись и создание файлов запрещены; на ABI 4+ запрещены TCP bind и connect) и фильтр seccomp (сокеты, fork, новые процессы, ptrace, сигналы, монтирование, удаление и переименование файлов, открытие на запись). Оба слоя переживают exec и действуют на код решения на любом языке. Отдельный контейнер-исполнитель не нужен: слои ядра ставятся непривилегированным процессом внутри контейнера приложения. `GET /api/v1/arena/sandbox` показывает, какие слои включились на стенде.
- Вердикты: OK, WA (неверный ответ), TLE (превышено время), MLE (превышена память), RE (ошибка выполнения), CE (ошибка компиляции, синтаксис). По каждому тесту — вердикт и время.
- Параллельно проверяется ограниченное число решений на процесс приложения, остальные ждут в очереди.

**Банк задач (FSP-39).**
- Задача — генератор варианта по зерну, условие, генератор тестов, эталонная функция и эталонное решение в виде кода. Уровни 1–3.
- Зерно варианта зависит от раунда, участника и задачи, поэтому два участника получают разные данные.
- Тесты: открытые примеры варианта и скрытые тесты, включая граничные и большие (отсекают медленные решения).
- В CI эталонный код каждой задачи проходит все сгенерированные тесты через песочницу.

**Раунды (FSP-40).**
- Открытый раунд работает постоянно: таймер у каждого участника свой, от момента входа.
- Раунд работодателя или платформы идёт по расписанию: общий старт и конец по серверному времени.
- Очки как в ICPC: сначала число решённых задач, при равенстве — меньший штраф. Штраф за задачу — минуты от начала до первого верного решения плюс фиксированный штраф за каждую неверную попытку до него. Ошибки компиляции штраф не дают.
- За последние минуты раунда по расписанию таблица для участников замораживается; свои результаты участник видит всегда.
- Отправка после окончания времени участника отклоняется.
- Разбор (эталонные решения и статистика) открывается участнику после окончания его времени.

**Рейтинг (FSP-42).**
- Glicko-2. Период рейтинга — одно участие. Соперники — задачи раунда с фиксированным рейтингом по уровню: решил задачу — победа, не решил — поражение.
- Пока неуверенность рейтинга велика, рейтинг помечен как предварительный. При долгом отсутствии неуверенность растёт.
- Рейтинг Arena на грейд не влияет. В подборке он входит в компонент «соревнования» вместе с баллом ФСП (берётся больший) и даёт строку объяснения.
- Антисписывание: решения одной задачи в одном раунде сравниваются после нормализации токенов (без комментариев, имена заменены). Почти совпадающие решения помечаются как подозрительные. Вставки большого фрагмента кода и уходы со вкладки записываются как сигналы. Пометка видна работодателю; результат не аннулируется автоматически.

**Работодатель и приватность (FSP-41).**
- Витрина: кандидаты с рейтингом Arena и подтверждённой категорией, фильтр по специализации, грейду, ФСП и минимальному рейтингу.
- Раунд работодателя: название, специализация, задачи из банка, время старта и длительность, приз.
- Кандидат по умолчанию участвует анонимно: в таблице и витрине он «Участник #XXXX», решения скрыты. Настройка «Показывать имя и решения в Arena» открывает имя и решения работодателям.
- «Пригласить» из таблицы и витрины — обычное приглашение с зарплатой; контакты раскрываются после принятия.

## Вне scope
- Java и Go: нужен отдельный образ исполнителя с компиляторами, после сдачи.
- Аннулирование результата модератором: роли модератора нет, подозрительные решения только помечаются.
- Предложение работодателем своей задачи с проверкой эталона: работодатель собирает раунд из банка.
- Задачи прошлых соревнований ФСП.

## Данные
- `arena_rounds` — раунд: название, описание, специализация, начало и конец, длительность участия, открытый или по расписанию, минуты заморозки, коды задач, компания-спонсор, приз.
- `arena_participants` — участие: раунд, кандидат, время входа и конца, решено, штраф, рейтинг до и после, отметка о пересчёте.
- `arena_submissions` — отправка: задача, язык, код, статус проверки, вердикт, тесты (вердикт и время каждого), время и память, разбор и его источник, сигналы антисписывания, пометка о похожем решении.
- `arena_ratings` — рейтинг кандидата: значение, неуверенность, волатильность, число участий, история.
- `candidate_profiles.privacy.show_arena` — показывать имя и решения в Arena.

## Критерии приёмки (EARS)
- WHEN решение пытается открыть сеть, запустить процесс, прочитать файл хоста или уходит в бесконечный цикл THE SYSTEM SHALL завершить его с вердиктом RE или TLE, не затронув стенд.
- WHEN решение потребляет память сверх лимита THE SYSTEM SHALL вернуть MLE.
- WHEN 50 решений отправлены одновременно THE SYSTEM SHALL проверить все без ошибок и записать время в отчёт.
- WHEN эталонный код задачи запускается на сгенерированных тестах THE SYSTEM SHALL вернуть OK на каждом (CI).
- WHEN два кандидата участвуют в одном раунде THE SYSTEM SHALL выдать им разные варианты одной задачи.
- WHEN кандидат отправляет решение THE SYSTEM SHALL вернуть вердикт по каждому тесту и разбор без перезагрузки страницы.
- WHEN кандидат перезагружает страницу THE SYSTEM SHALL сохранить черновик кода.
- WHEN отправка приходит после окончания времени участника THE SYSTEM SHALL отклонить её.
- WHEN результат участника меняется THE SYSTEM SHALL обновить таблицу у других участников без перезагрузки.
- WHEN участие закончилось THE SYSTEM SHALL пересчитать рейтинг Glicko-2 и открыть разбор задач.
- WHEN два решения одной задачи в раунде совпадают после нормализации THE SYSTEM SHALL пометить их как подозрительные.
- WHEN кандидат не включил показ в Arena THE SYSTEM SHALL скрывать его имя и решения от работодателя до принятия приглашения.
- WHEN работодатель создаёт раунд THE SYSTEM SHALL показать его кандидатам, а после раунда показать работодателю таблицу с кнопкой «Пригласить».

## Интерфейсы
Все пути с префиксом `/api/v1/arena`.
- Кандидат: `GET /rounds`, `POST /rounds/{id}/join`, `GET /rounds/{id}`, `POST /rounds/{id}/run`, `POST /rounds/{id}/submit`, `POST /rounds/{id}/finish`, `GET /submissions/{id}`, `GET /me`, `PUT /me/settings`.
- Все роли: `GET /rounds/{id}/leaderboard`, `GET /rounds/{id}/stream` (SSE), `GET /rounds/{id}/editorial`.
- Работодатель: `GET /top`, `POST /rounds`, `GET /candidates/{profile_id}`.
- `judge.judge(language, code, tests, **limits)` → `JudgeResult` с вердиктами (синхронный вариант — `judge.judge_sync`); `problems.variant(code, seed)` → условие, примеры, тесты; `rating.update(player, results)` → новый рейтинг.

- `tests/test_arena/test_sandbox.py` — сеть, процессы, `fork`, чтение файлов хоста, бесконечный цикл, память, синтаксис, большой вывод; вердикты OK/WA/TLE/MLE/RE/CE.
- `tests/test_arena/test_problems.py` — эталон каждой задачи проходит все тесты нескольких вариантов через песочницу; варианты разных участников различаются.
- `tests/test_arena/test_rating.py` — Glicko-2 на синтетике: победы поднимают рейтинг, неуверенность падает, предварительный статус, рост неуверенности при отсутствии.
- `tests/test_arena/test_api.py` — сквозной сценарий раунда: вход, примеры, отправка, вердикт, таблица, заморозка, отказ после конца, разбор, рейтинг, похожие решения, приватность, раунд работодателя и приглашение из таблицы.
- `scripts/load.py --arena` — 50 одновременных отправок, время в `docs/validation/load.md`.
