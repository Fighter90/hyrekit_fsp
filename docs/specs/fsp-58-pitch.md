# Питч и инструкция для жюри

Linear: FSP-58 · веха Финальная сдача. Пункты ТЗ: защита (питч, 10 % оценки), 3.3 (сквозной сценарий), 3.4 (методика и валидация).

## Цель
Жюри за 10 минут выступления понимает продукт, механику теста и цифры валидации, а после — само проверяет стенд без помощи команды.

## Для кого
Эксперты жюри хакатона ФСП: слушают питч и проверяют прототип на своём компьютере.

## Сценарии
1. Докладчик показывает 23 слайда по заметкам; выступление укладывается в 10 минут.
2. Эксперт открывает `docs/jury.md`, проходит экспресс-тест на стенде и находит своего гостя в подборке работодателя.

## Правила и числа
- Презентация собрана на официальном шаблоне ФСП «ЛЦТ 2026» (Montserrat, палитра шаблона, логотипы партнёров) скриптом `docs/presentation/build/build.py`; слайды шаблона заполняются, а не перерисовываются.
- Сюжет (23 слайда): титул → о команде и решении → команда → история, выбор задачи, сложности → коротко о решении → проблема и решение → как это работает → демо кандидата → демо работодателя → Code Arena → механика теста → устойчивость к утечке → валидация грейда → объяснимый подбор → технологии → архитектура → вход через ФСП ID → уникальность → бизнес и маркетинг → мобильная версия → надёжность и качество → планы развития → попробуйте сами (QR-коды стенда и репозитория).
- Числа методики — только из `src/app/assessment/engine.py`, `src/app/matching/service.py` и `docs/validation/results.md`; нагрузка — из `docs/validation/load.md`.
- Code Arena, вход через ФСП ID и интеграция с GigaChat и YandexGPT показываются как готовые: они работают на стенде. Боевой Keycloak ФСП, модерация работодателей, адаптивный тест и ATS — как планы.
- Оформление — из шаблона ФСП: фиолетовый `#520978`, тёмный `#310F53`, розовый `#FF0053`, лиловый `#8A83D1`; скриншоты — реальные экраны стенда hyrekit.ru (десктоп и телефон 390 px).
- Демо-видео не делаем в этой задаче и не упоминаем как готовое.

## Вне scope
- Демо-видео 3–5 минут — отдельный шаг FSP-58 после выкатки стенда.

## Данные
Файлы: `docs/presentation/HyreKit_pitch.pptx` (с заметками докладчика), `docs/presentation/HyreKit_pitch.pdf`, скриншоты стенда и QR-коды `docs/presentation/assets/`, скрипты сборки `docs/presentation/build/`, `docs/jury.md`.

## Критерии приёмки (EARS)
- WHEN докладчик открывает pptx THE SYSTEM SHALL показать 23 слайда на шаблоне ФСП, у каждого заметки докладчика на 20–40 секунд речи.
- WHEN число на слайде относится к методике THE SYSTEM SHALL совпадать с кодом или `docs/validation/results.md`.
- WHEN эксперт открывает `docs/jury.md` THE SYSTEM SHALL дать ссылку на стенд, демо-аккаунты, шаги экспресс-теста и сценарий работодателя.
- WHEN читатель открывает README THE SYSTEM SHALL вести к презентации и инструкции для жюри.

## Интерфейсы
Нет изменений API и кода.

## План тестов
Ручная проверка: pdf рендерится постранично без вылезающего текста и без подсказок «Образец текста» из макетов шаблона; `markitdown` показывает заметки на всех слайдах; цифры сверены с `engine.py`, `service.py`, `results.md`, `load.md`; `scripts/validate.py` не меняет `results.md`.
