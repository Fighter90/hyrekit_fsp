# Питч и инструкция для жюри

Linear: FSP-58 · веха Финальная сдача. Пункты ТЗ: защита (питч, 10 % оценки), 3.3 (сквозной сценарий), 3.4 (методика и валидация).

## Цель
Жюри за 10 минут выступления понимает продукт, механику теста и цифры валидации, а после — само проверяет стенд без помощи команды.

## Для кого
Эксперты жюри хакатона ФСП: слушают питч и проверяют прототип на своём компьютере.

## Сценарии
1. Докладчик показывает 15 слайдов по заметкам; выступление укладывается в 10 минут.
2. Эксперт открывает `docs/jury.md`, проходит экспресс-тест на стенде и находит своего гостя в подборке работодателя.

## Правила и числа
- Сюжет: проблема → обратная механика → путь кандидата → путь работодателя → Code Arena → механика тестирования → устойчивость → валидация → подбор → нагрузка → архитектура и GigaChat → антифейк и ATS → что дальше с ФСП → ссылки.
- Числа методики — только из `src/app/assessment/engine.py`, `src/app/matching/service.py` и `docs/validation/results.md`; нагрузка — из `docs/validation/load.md`.
- Code Arena, ФСП ID на Keycloak, модерация работодателей и ATS показываются как планы: в `main` их нет.
- Фирменный стиль ФСП по [DESIGN.md](../../DESIGN.md): графитовая основа, синий `#402FFF`, красный `#EC1D35`, шрифты TDAText и JetBrains Mono, логотип ФСП без перерисовки.
- Демо-видео не делаем в этой задаче и не упоминаем как готовое.

## Вне scope
- Демо-видео 3–5 минут — отдельный шаг FSP-58 после выкатки стенда.

## Данные
Файлы: `docs/presentation/HyreKit_pitch.pptx` (с заметками докладчика), `docs/presentation/HyreKit_pitch.pdf`, скриншоты стенда `docs/presentation/assets/`, `docs/jury.md`.

## Критерии приёмки (EARS)
- WHEN докладчик открывает pptx THE SYSTEM SHALL показать 12–15 слайдов, у каждого заметки на 40–50 секунд речи.
- WHEN число на слайде относится к методике THE SYSTEM SHALL совпадать с кодом или `docs/validation/results.md`.
- WHEN эксперт открывает `docs/jury.md` THE SYSTEM SHALL дать ссылку на стенд, демо-аккаунты, шаги экспресс-теста и сценарий работодателя.
- WHEN читатель открывает README THE SYSTEM SHALL вести к презентации и инструкции для жюри.

## Интерфейсы
Нет изменений API и кода.

## План тестов
Ручная проверка: pdf рендерится постранично без вылезающего текста; `markitdown` показывает заметки на всех слайдах; цифры сверены с `engine.py`, `service.py`, `results.md`, `load.md`; `scripts/validate.py` не меняет `results.md`.
