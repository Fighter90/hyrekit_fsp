# Нагрузочная проверка

Linear: FSP-56. Скрипт — [`scripts/load.py`](../../scripts/load.py): виртуальные пользователи параллельно крутят сценарий работодателя (подборка, поиск по банку, карточка, категории) и кандидата (профиль, вакансии, справочник). Вход выполняется один раз на роль: эндпоинты входа защищены rate limit и в нагрузку не входят.

Стенд: `docker compose up` из корня репозитория — PostgreSQL 16, Redis, API на 2 воркерах uvicorn, 120 синтетических кандидатов из демо-данных. Машина: 4 vCPU, 16 ГБ, генератор нагрузки на той же машине. Прогон 2026-10-10.

## Выводы

- Ошибок нет ни в одном прогоне; при 10 пользователях p95 всех операций не выше 65 мс, включая подборку с объяснением.
- При 50 пользователях пропускная способность упирается в 2 воркера API и генератор нагрузки на тех же 4 vCPU: p95 растёт до 0,7 с из-за очереди, а не из-за отдельных медленных запросов (p50 — около 0,17 с).
- Для хакатонной нагрузки (десятки пользователей) хватает ВМ из [deploy/yc/README.md](../../deploy/yc/README.md). Запас по p95 даёт увеличение числа воркеров `uvicorn --workers` по числу vCPU.

Повторить на стенде: `python scripts/load.py --base https://hyrekit.ru --users 20 --duration 60`.
